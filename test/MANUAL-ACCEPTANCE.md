# Manual deployment acceptance

`npm test` provides isolated synthetic module checks. Deployment acceptance is separate: use a disposable Capri workspace with this module explicitly enabled/applied and the current native session metadata. Do not reuse the archived scripts or register synthetic session identities in a live workspace.

1. Check `workspace_status` and the effective tool catalogue. `fuzz_run` and `fuzz_result` should resolve to this module's extensions; `fuzz_options` and `fuzz_input` remain core. Vocabulary tools and the on-demand `fuzzing` role should be visible only where this module is enabled. Ordinary module configuration edits must be applied before checking the resulting catalogue.
2. Use synthetic local proxy traffic to obtain a capture through `proxy_traffic_read`. Store observed words, add an explicitly identified inferred candidate batch, generate a named revision, then list and read that exact revision. Inspect the returned source references and module-owned storage paths.
3. Against an operator-authorized local fixture, call `fuzz_run` with explicit wordlist paths and markers. Repeat using the generated `wordlist` name/revision extension. Confirm one core operation/process per call, direct traffic, recorded output, and failure on an existing output path. Read the operation through current `operation_*` tools. Use the documented request context returned/advertised by this installed Capri version.
4. Inspect the saved run with plain `fuzz_result`, then filtered compact, summary and table views. Include matching rows beyond the first page. Confirm filters run before pagination, summary covers every match, cursors reject a changed query, and raw evidence remains byte-for-byte unchanged.
5. Explicitly disable/apply this module in the disposable workspace and start a fresh connection if required by the desktop. Confirm vocabulary tools and role disappear while core `fuzz_*` tools remain, including access to that workspace's saved raw run. Do not enable the module in unrelated workspaces for this check.
6. If testing native delegation, assign a bounded task and deliverable to the installed `fuzzing` role through the current desktop/native tools. Confirm its concise role and optional skill are available. Autonomous continuous work is an explicit operator choice; the module's default does not start a perpetual agent.

Report the framework/module revisions, platform, effective tool catalogue and actual results. These steps are a test specification, not a claim that deployment or live acceptance has been performed by the module unit suite.
